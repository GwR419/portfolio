WEBSITE REFLECTIVE ESSAY

Challenges

Throughout this semester I've learned to build a website from scratch. My first hurdles were flexboxes — CSS layout felt opaque at first. GitHub was also intimidating when I was thinking of it as something bigger than a push/pull tool. HTML's sensitivity to syntax was another early lesson. WordPress felt easier at the surface for someone with no HTML background, but for me it was more frustrating — far less freedom than raw code.

Advantages

GitHub + HTML gives total freedom over layout and placement. WordPress locks you into templates. The one thing WordPress has going for it: open a browser, log in, start editing. With HTML you need to set up GitHub, learn its commands, and manage your files carefully. But HTML teaches you how the web actually works — WordPress just teaches you how to fill boxes.

Layout and Organization

GitHub requires you to learn spacing units (em, px, %) and placement logic. WordPress lets you pick a theme and drag things around. Nav bars in HTML take real planning — multiple files, flex containers, explicit ordering. In WordPress you just drag pages into a menu. Both valid, very different skill ceilings.

Skills

WordPress needs almost none — it's a UI. HTML/GitHub requires directory knowledge, coding fundamentals, and understanding Git commands well enough to not push when you mean to pull. The technical floor is higher but so is the ceiling.

What I Want to Improve

CSS and flexboxes are still my weakest area — they cause the most friction when I'm trying to get layouts right. I also want to get more comfortable in WordPress so I can move fluidly between both approaches. And I want to write tighter, more readable code overall.
